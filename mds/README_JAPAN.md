## 2. 핵심 판단 기준

### 2-1. 행사 대응 원칙
- SusHi Tech는 단순 전시보다 **business matching / collaboration opportunity** 성격
- 일본 완제품보다 **한국에서 검증 중인 코어 제품 + 일본 현지화 가능한 구조**를 보여주는 것이 중요
- 일본 파트너가 볼 포인트:

  - 다국어/역할 분리가 되는가
  - 데이터/정책 분리가 가능한가

## 4. Master Core 엔진 설계

### 4-A. 템플릿 엔진 ✅ Week 1 완료

```python
# 구현 완료
- InspectionTemplate (점검 템플릿)
  - 국가별 분기: KR / JP / GLOBAL
  - 부동산 유형별 분기: RESIDENTIAL / COMMERCIAL / OFFICE
  - 다국어 이름: name, name_en, name_ja

- TemplateSection (템플릿 섹션)
  - 공간별 분류: ENTRANCE, LIVING_ROOM, KITCHEN, etc.
  - 다국어 이름: name_ko, name_en, name_ja
  - 필수/선택 설정

- TemplateItem (점검 항목)
  - 항목 타입: PHOTO, CHECKBOX, TEXT, SELECT, NUMBER
  - 책임 태그: LANDLORD, TENANT, NEGOTIABLE
  - 최소/최대 사진 수 설정
```

### 4-B. 리포트 엔진 ✅ Week 2 완료

```python
# 구현 완료
- GeneratedReport (생성된 리포트)
  - report_type: MOVE_IN / MOVE_OUT / COMPARISON
  - language: ko / en / ja
  - status: PENDING / PROCESSING / COMPLETED / FAILED
  - PDF 파일 저장

- ReportShare (리포트 공유 링크)
  - token: UUID 기반 공유 토큰
  - expires_at: 만료 시간 설정
  - max_downloads: 다운로드 횟수 제한
  - password_hash: 비밀번호 보호 (선택)

기능:
- PDF 출력 ✅
- 공유 링크 출력 ✅
- 다국어 라벨 출력 ✅
- 항목별 사진/메모 연결 ✅
- 비교 결과 표시 ✅
- 책임 태그 표시 ✅
```

기존 구현:

#### PART 2. 계약 중 (入居中)

| 항목 | 내용 |
|------|------|
| 사용 목적 | 거주 전용 |
| 절대 금지 | 위험물, 중량물, 소음, 맹수, 반사회적 세력 |
| 승낙 필요 | 애완동물, 공용장소 물건 |
| 통지 필요 | 동거인 추가, 장기 부재 |
| 수리 | 경미한 수리는 임차인, 그 외 임대인 |

#### PART 3. 퇴거 시 (退去時)

| 항목 | 내용 |
|------|------|
| 퇴거 절차 | 사전 통지, 열쇠 반환 |

## 10. 앱 전환 원칙

### 10-1. 흔한 실패 패턴 (피해야 할 것)

- 웹 화면을 그대로 앱으로 옮김
- 현장 UX를 고려하지 않음
- 촬영/비교/리포트보다 메뉴 구조를 먼저 만듦
- 국가별 분기 요구를 하드코딩으로 처리

### 10-2. 권장 전환 원칙

- 앱은 **"기록 생산용"**으로 설계
- 웹은 **"관리/검토/운영용"**으로 설계
- 공통 로직은 백엔드와 공통 도메인 모델에 배치
- 국가별 차이는 템플릿/설정/출력층으로 분리

### 10-3. 앱의 핵심 사용자 흐름

```
1. 사건 생성
2. 자산 유형 선택 (주거 / 상가)
3. 국가/템플릿 선택
4. 공간별 촬영
5. 항목 체크 및 메모
6. 누락 경고 확인
7. 업로드 및 무결성 기록
8. 리포트 생성/공유
```
